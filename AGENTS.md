# AGENTS.md

Instructions for AI coding agents (Claude Code, Codex, Copilot, Cursor…) and for the humans driving them. Read this whole file before changing anything. If an instruction here conflicts with a request, stop and ask the human.

## What this project is

**Archivo 115** (Spanish) / **Archive 115** (English), deployed at https://e-115-archive.vercel.app: a static, bilingual (Spanish / English), spoiler-safe guide to Call of Duty Zombies, styled like a 2000s Flash site. Built with Astro 7. Content is Markdown, rendered through custom remark directives. There is no backend, no database, no CDN, no tracking.

## Golden rules

1. **Never invent game facts.** Every factual claim in `src/content/` (locations, costs, rounds, quest steps, quotes, story events, release dates) must be verifiable on the [Call of Duty Wiki](https://callofduty.fandom.com/). If you cannot verify it, do not write it. Tips and opinions must read as tips ("good spot to…"), never as facts. List the wiki pages you used in the pull request.
2. **Spoilers stay locked.** Bosses, story twists and Easter egg steps go inside `:::spoiler` or a locked `:::dossier`. Never put a `##` heading inside a spoiler (it leaks into the table of contents). Never reveal a locked dossier's real name in its `codename` or `teaser`. Quest checklists (`:::checklist`) also go inside a spoiler, and keep the same `id` and number of steps in both languages.
3. **Both languages, always in sync.** Any change to `src/content/**/es/…` needs the equivalent change in `src/content/**/en/…` (and the other way round): same files, same front matter data, same images, same spoiler/dossier `id`s, same number of facts. English files reuse the Spanish ids. The content tests enforce this.
4. **Code in English, content in the reader's language.** Identifiers, comments, commit messages and all repository documentation (README, CONTRIBUTING, `docs/`, `.github/` templates, this file) are in English only; in them the project is "Archive 115". Spanish belongs only in `src/content/**/es/` and the Spanish UI strings. Guide text is in neutral Spanish (`tú` / `ustedes`, never `vosotros`) or plain English.
5. **Every behaviour change ships with tests.** Logic → Vitest (`tests/unit`). User flows → Cypress (`cypress/e2e`). Do not delete or weaken a test to make it pass; fix the code, or explain to the human why the test was wrong.
6. **Stay static and self-contained.** No servers, no API keys, no third-party scripts or CDNs, no analytics, no video embeds or video links. The only external links content may add are Call of Duty Wiki articles (character cards use `href`); the site is a guide, not a wiki. Fonts come from `@fontsource`, images from `public/images`.
7. **Real images, always credited.** Images are only added through `scripts/images.manifest.json` + `npm run images`, which downloads them and writes `src/data/image-credits.json`. Never hand-edit the credits file and never commit an image without a credit.
8. **Accessibility and motion.** Keep text contrast, `alt` text, keyboard access and `prefers-reduced-motion` support. New animations must switch off under reduced motion.
9. **Responsive is not optional.** Every page must work from 375 px phones to large desktops with no horizontal scroll. `cypress/e2e/responsive.cy.ts` checks six devices.

## Commands

```bash
npm install
npm run dev            # http://localhost:4321 (Spanish at /, English at /en/)
npm run test:unit      # Vitest: directives, i18n, narrator, spoilers, content validation + ES/EN parity
npm run test:e2e       # build + Cypress (home, guides, narrator, language, responsive, integrity)
npm test               # both
npm run images         # download images listed in scripts/images.manifest.json
./deployment/deploy.sh # or deployment\deploy.cmd on Windows: run the site in a container
```

These work in any shell and OS, VS Code's terminal included: `cy:run`/`cy:open` go through `scripts/cypress.mjs`, which clears the `ELECTRON_RUN_AS_NODE` variable VS Code sets. Call `npm run cy:run`, not `npx cypress run`. CI runs unit tests and the build on Linux, macOS and Windows, so keep code OS-neutral: build paths with `path.join`, and normalise them to `/` before splitting or comparing.

## Definition of done

Before you say a task is finished:

- [ ] `npm run test:unit` passes.
- [ ] `npm run test:e2e` passes (or explain exactly which spec could not run and why).
- [ ] New logic has unit tests; new user-visible behaviour has a Cypress test.
- [ ] Content changes exist in **both** languages and every new fact has a wiki source.
- [ ] No new `##` inside spoilers, no unlocked boss names, no video links.
- [ ] Pages still work on a 375 px phone and a 768 px tablet.
- [ ] You reported what you verified and what you could not, without overstating it.

## Adding a map guide (checklist)

1. Copy `docs/map-template.md` to `src/content/maps/es/<era>/<slug>.md` and `src/content/maps/en/<era>/<slug>.md`.
2. Add images to `scripts/images.manifest.json` → `npm run images`.
3. Write the Spanish guide, verifying every fact against the wiki. Translate it into English, keeping the same spoiler ids (`{id="…"}` in English).
4. Required sections (H2), in this language pair: *Antes de empezar / Before you start*, *Dónde estás y quién eres / Where you are and who you are*, *El objetivo / The objective*, *Enemigos y jefes / Enemies and bosses*. Include at least one locked dossier, an Easter egg spoiler, `:::narration` lines and a narrator `intro`.
5. Set `status: guide` in both files, run the tests, check both language pages on phone and desktop.

## Things that will break the site

- Using `data-intro` on anything other than the Flash intro (the intro script looks for it).
- Changing a spoiler `id` in only one language (progress stops carrying over; tests fail).
- Changing a heading text and relying on its old anchor (anchors are generated from heading text).
- Adding pages without a `path`/`lang` to `Base.astro` (the language switch and `hreflang` depend on them).
- Hard-coding `/` URLs instead of `url()` from `src/lib/site.ts` (breaks GitHub Pages sub-path hosting).
